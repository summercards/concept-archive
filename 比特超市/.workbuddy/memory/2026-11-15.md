- 自动取景别用包围球半径：宽而扁的排布（42×3 m）会被推得极远；要按相机朝向投影出横/竖/深再算。

## 第三轮：把预览的观感往游戏靠（PMREM + 后期）

**起因**：用户问「预览和游戏内品质差为什么那么多」。答案是管线长度差：
游戏 = 几何 → 自定义着色 → 光照/阴影 → 后期合成 → 屏幕（5 段）；
预览原来只有 3 段，且每段降级。逐项证据（都在原文件里）：
- 环境光：`r.environment` 挂 PMREM（天空 + `interiorEnv` 室内探针）；预览原为一盏半球光顶替。
- 着色：`onBeforeCompile` 注入 ORM/湿润/宏观脏污；预览是 MeshStandardMaterial + 族基色兜底。
- 阴影：`quality.shadow` 4096（封顶 maxTextureSize）、PCF、bias -1.2e-4、normalBias .02、`planarReflection` RT；预览 1024 PCFSoft。
- 后期：合成 pass 的 uniform 有 `tScene/tBloom/tBlur/tStreak/tDirt` + `uBloom/uDirt/uStreak/uFlare/uCA/uVignette/uAgxMix`，渲染器本身 `toneMapping = NoToneMapping`（色彩映射在合成里做，AgX/ACES 混）。

**这一轮的实现**：
- `GL.toneMapping = NoToneMapping`，场景先画进 HalfFloat RT（可选 4× MSAA），再走 post 链：亮部提取（1/4 分辨率）→ 3 轮可分离模糊 → 合成（曝光 → 叠 bloom → ACES → 饱和 → 暗角）。
- 天空真的烘成 PMREM：`PMREMGenerator.fromScene(只含 sky 的临时场景)`，太阳改高度时重烘（旧的 RT 要 dispose）。
- 棚拍环境探针（另外 3 个 3D 预览共用一张）：冷色穹顶 + 暖主光板 + 冷边光板，`fromScene` 一次后缓存。
- `HOST_EXPOSURE = 1.55` 补偿原版的眼睛适应（tAdapt），不是资产里的数。
- 太阳圆盘给到 HDR 亮度（`new Color(5.2,4.7,4.0)`），否则亮部提取抓不到，bloom 无从谈起。

**新踩的坑**：
- ShaderMaterial 里可以直接 `#include <colorspace_fragment>`：three 会给所有非 Raw 材质注入 `linearToOutputTexel`。前提是渲染器 `outputColorSpace` 设对、且这一步放在最后。
- 渲染到 RT 时 three 用的是 **RT 的 texture.colorSpace**（默认 Linear），不是 renderer 的；所以 HDR 进 RT 不会被提前压色。
- 雾色不能直接用 `SKY.fog`：低太阳时天空地平线是橙的，灰蓝雾会把远处地面染成对不上的灰带。改成按相机方位取天空地平线色（`cHor.lerp(cAway, …)`），每帧同步。
- 预览里 3D `camera` 不是局部变量，是 `v.camera`；写错会静默落到 `.pv-fail`（页面会显示「预览起不来: xxx is not defined」）。


## 第四轮：把程序化材质真的烘出来（第 10 个资产 material-baker）

**起因**：用户问「为什么每个道具上的材质、贴图、法线都没有，全变成纯色了」，并明确要求「所有内容必须还原」。
根因：原工程的贴图不是图片文件，是 GLSL 在 GPU 上烘的；之前预览只从台账拿到 `toStandard()` 的参数，贴图全丢，所以是纯色塑料。

**做了什么**：
- `tools/extract_baker.py` 从原 HTML 逐字抽：`Qy`(quad 顶点) / `e3`(surf 前导 5283) / 27 个 `Tn.*` 族函数(34385) / `t3`(main) / `i3`(Sobel 法线 615) / `s3`(copy) / `dA…yA`(7 段材质补丁 7446) → `assets/code/material-baker.js`。
- 唯一改写：原版 `WebGLRenderTarget({count:3})` 的 MRT，本机 three 是 **r160 没有 count** → 拆成 3 次 `uSel` 选择的单目标 pass。
- `tools/baker_harness.js` 重写宿主：`bake(family)` = surf×3 + copy×2 + normal×1；`material(id)` = MeshStandardMaterial + 台账 uniform + `onBeforeCompile` 打补丁。
- 预览侧 `painted()` 优先走烘焙器，失败才回退纯色；材质球 UV 按 0.42m 半径换算米制，地面/道具 UV 按米铺开。
- 新增烘焙器详情预览 `bakerPreview`：三宫格 albedo / normal / ORM + 族切换。
- `build/verify.mjs` 加第 8 节：把原 HTML 的模板字面量重新抠一遍（含 `${n3}` 展开、MRT 改写），与模块导出常量**逐字**比 → 46 项全过。
- 验证数字改为 `build/verify-result.json` 落盘，`bundle.py` 读取，页面文案不再手写 39。

**新踩的坑**：
- 族函数本身是模板字符串，内部插了共享片段 `${n3}`（paintDmg）；不展开会在 shader 里留下 `$` 直接编译失败。
- `RawShaderMaterial` + `GLSL3` 必须显式声明 `in vec3 position`，否则要么和 three 注入的 `attribute` 冲突、要么取不到属性。
- `material.clone()` 不复制 `onBeforeCompile`：族色模式曾整片变纯色，改用 `painted(id,{color})` 并把 color 纳入 cache key。
- 缩略图（thumb）布局不能复用大图坐标：3 段长文案会撞车；缩略图改成裁切铺满格子（cover），详情页才保正方。
- `grep` 对 `previews.js` 会静默失效（被判成 c program text + 含 NUL），改用 `grep -a` 或 Python 读。
