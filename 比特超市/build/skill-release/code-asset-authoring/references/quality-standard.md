# 原创资产质量标准与验收证据

## 1. 选择正确的质量门

把目标定义为“新设计也达到网页的真实结构、表面尺度与预览检验标准”，不要满足于外包围盒相近或材质名称齐全。

区分下列两类验收，不跨版本推定等价：

| 门 | 范围与依据 | 允许结论 |
| --- | --- | --- |
| catalog 门 | 在资产库真实 r160 棚拍链中，检查独立资产构造、材质、相机、变体、交互及运行证据。 | 只声明对应 id/options/seed 的独立预览质量。 |
| r180 full-scene 门 | 在恢复后的原版整机 r180 环境中，另验灯光、材质、集成、行为与画面。 | 只有整机实测才能声明场景集成质量；catalog 通过不能替代。 |

把以下内容视为用户提供的项目现状，不当作本次已复测结果：当前原版 36 个 props 已走 M3/Yg 链真实构造；原版整机 r180 仍待恢复。不要把原版数量伪装成新资产完成数，也不要声称两套环境已经等价。

把新资产的 baseline 设为 `type: 'new-design'`。使用 design contract 和可信 reference quality comparators 验收，不把“与原版逐点差异 = 0”当作原创质量指标。保留原版哈希与提取基线用于回归隔离，而非要求原创几何复刻。

## 2. 先完成可检验的设计契约

在写几何前明确以下内容，并填写 [契约模板](../assets/asset-contract.template.json)。以下清单是完整质量目标，不是 check/verify 已自动全部覆盖的功能表。先 scaffold，再实现 source/填全契约，经静态 check 后显式运行 `python3 "$ROOT/tools/build_authored.py" --root "$ROOT"` 生成 authored.js，最后 verify；不要直接验证未实现脚手架或旧生成产物。构建器仅面向可信本地源码的静态约束；不是安全沙箱，工厂不隔离恶意代码。

1. **用途、尺寸与轴原点**：写清目标功能、X/Y/Z 尺寸、底面中心原点、Y 向上、+Z 正面、落地面、可接近方向及尺寸误差依据；动态/新材质能力若尚未由宿主提供，明确记为未实现或待能力补齐。
2. **轮廓与比例**：描述正/侧/后三个方向的轮廓、体块分层、视觉重心；附原创草图或文字设计依据，不仅写“工业风”。
3. **功能层级与 requiredParts**：列出外壳、支撑、门/抽屉、层板、把手、锁、铰链、接口等实际需要的部件。对每件写尺寸、位置、父子关系、用途与查找名。
4. **开口与厚度**：量化壳板、门板、柜口翻边、背板、层板厚度，门缝及内腔深度；明确可见内表面及门开后的结构。禁止把门画在实心盒表面却宣称可开门。
5. **连接与装配**：声明脚座、焊接/螺栓/卡扣、铰链轴、把手固定、管线接头的装配关系；消除悬浮、无端穿插、零厚面及无法工作的转轴。
6. **板缝与门锁**：按参考尺度确定板缝、边折、铰链间距和锁体凸出；区分真实几何与贴花职责，不把黑色线条一律当结构缝。
7. **UV 与米制表面**：声明每种表面的纹理密度、方向、重复策略、标签尺寸及贴花偏移；使用度量参考实测，不用默认 BoxGeometry UV 冒充一致表面尺度。
8. **材质**：列出宿主材质标识、粗糙度/金属感/透明/发光职责、贴花来源与版权；说明共享资源所有权和着色钩子需求。
9. **碰撞与挂点**：定义 collider 的 min/max/surface、可进入开口、部件运动时更新规则、socket 的坐标/朝向/用途。
10. **变体与 seed**：声明所有 options、默认值、合法组合、seed 的变化范围及不变量；避免换色名称掩盖未完成的几何变体。
11. **动态**：声明运动范围、转轴/滑轨、状态入口、update/reset/dispose、dt 单位、碰撞和挂点联动；静态设计明确不适用。
12. **LOD 与预算**：按实际参考资产测量三角形、draw calls、材质/纹理数量与显存、构建及帧开销，定义本资产各 LOD 的保留/简化部件和切换依据。无 LOD 时写明原因与目标场景限制。

为维修柜保留柜体空腔、双门独立厚度、翻边/框、层板、门缝、铰链与锁把；为灭火器站保留底座/框、固定带或支架、器体/阀/软管及可读标识；为工作台保留台面厚度、承重框架/横撑、脚座及实际工具或收纳部件。根据用户用途增减，不强行给所有资产套同一零件清单。

没有足够依据时先列未知项并确认关键尺寸；不要悄悄把空腔、功能件或动态删掉以降低工作量。允许在设计阶段提出简化，但必须同步修改经确认的契约及目标质量门。

## 3. 选择并实测可信质量对照

- 在指定 root 内挑选功能接近、尺度接近、可真实加载的参考资产。记录 id、来源链、options、seed、Three 版本、材料/烘焙链、相机和图片路径。
- 区分“设计参考”与“质量对照”：概念图只能帮助外形设计，不能证明开口厚度、UV、法线、碰撞或运行质量。
- 对照功能层级完整度、壳体/五金尺度、几何厚度、连接可信度、贴花可读性和渲染开销，不要求拓扑/顶点坐标一致。
- 在相同棚拍灯光、渲染器、背景、分辨率、色彩空间、曝光和相机方向/FOV 下比较。完整展示各资产时记录各自距离与归一化方式；比较物理尺度时另用同一米制标尺或同距离镜头，防止自动 fit 隐藏尺寸差异。
- 测量后填写预算的 referenceMeasurements、limits 和 rationale；按资产用途、可见距离和细节密度决定限制。禁止把某个参考的数字或统一“三角形小于 N”当成所有资产的硬阈值。
- 没有可信参考或缺少实际测量时标为未执行/待补证据；不要把空列表、未知预算或 null 当作零成本通过。

## 4. 几何与元数据门

逐条报告 pass、fail、未执行，并附实际数值及证据：

- **有效实例**：build 返回 `THREE.Object3D`，assetId/authored 正确，至少存在真实可见几何；空 Object3D、只有名字的部件与退化面不通过。
- **finite 与法线**：检查 position、normal、UV、变换、bbox 全部 finite；检查索引边界、零面积面、近零/异常法线与非均匀/负缩放后的朝向。以灰模和线框补验裂缝、反面、意外重叠和面密度。
- **非空 bbox 与变体包络**：从实际几何求模型局部 bbox，检查三轴正跨度；默认状态对照 `contract.size` 名义尺寸、底面 y=0 与原点，变体对照匹配的 `contract.variantEnvelopes`。数组项形如 `{options:{drawerOpen:0.12}, min:[...], max:[...], size:[...]}`，size 可选；按实际资产填写，不给维修柜添加虚构抽屉。每次 build/影响尺寸的 update 后更新 `userData.size` 为真实 bbox；不强迫展开变体仍保持默认尺寸或中心，不以元数据伪造通过。
- **真实结构**：按契约逐项检查空腔、板厚、开口、倒角、功能件、装配与门锁；以可观察结构通过，不以 mesh 数量通过。
- **requiredParts**：验证每个名称仍可查询且有真实几何或合理子树；合批后不能丢失动态/验收部件。
- **UV 与表面尺度**：用棋盘格或已知米制纹理比对各面密度、方向和接缝；检查裸 BoxGeometry 路径、倒角、管线端盖和小尺寸贴花。声明可接受的无 UV 材质用途，不能全局跳过。
- **collider corners**：对每个 AABB 构造全部八角，经过其声明空间变换后检查位置、有限性、正跨度、与目标实体/开口的关系及总体覆盖；不能只看中心或总 bbox。动态 collider 要在端点和中间姿态再次检查。
- **sockets**：变换到模型/世界坐标复核位置、朝向、功能接触及活动部件联动；socket 不应落在错误板面或空中。
- **确定性**：独立重新构建同 seed/options，比较规范化几何、层级、材质分配及元数据摘要；用另一 seed 验证仅允许变化的部分改变。排除 UUID/时间戳等非设计字段，记录规范化方式。

## 5. 真实视觉门

在真实网页/独立预览器中加载最终生成产物，不用设计图、离线示意图或旧截图冒充。至少保存：

- 三个明确方位的最终材质 PNG：正面三分之四、背面三分之四、侧面；如有内腔或重要顶面，补开门/俯视图。
- 至少一张相同相机的 clay 灰模 PNG 和一张 wire 线框 PNG；使用不改原共享材质的预览覆盖方式，检查后恢复。
- 关键功能件、标签、板缝、开口厚度与接头近景；动态资产保存关闭/中间/开启证据，重要变体保存代表图。

给每张证据绑定 assetId、source/contract 摘要、options、seed、相机参数、renderer/Three 版本、渲染设置及测试命令。确保截图不裁切、不隐藏背面、无占位物和加载错误；清楚区分合成图与真实渲染。

打开并实际查看图片，逐项对照契约与可信参考：检查轮廓、比例、板厚、倒角、五金、内腔、UV 密度、材质层次、贴花、阴影接触和表面缺陷。若无法观察截图，标为“未执行：未完成真实视觉检查”，不能依据 PNG 存在或像素非空置 visual pass。

不要把“截图脚本成功”当成“视觉通过”；不要以原版逐点零误差作为原创外观指标。失败时指出具体图、位置、问题、修复及复测结果。

## 6. 运行、动态、变体与资源门

区分已实现自动检查与必须另补的证据：

| 层级 | 实际范围与限制 |
| --- | --- |
| doctor/check | 静态项目/依赖识别、schema/路径/源码约束及契约基本一致性；不执行 authored build，不证明几何、UV 或契约全部完成；check 不生成 authored.js。 |
| verify geometry | 真实 build，检查 finite attributes、单位法线、索引/退化面、bbox/元数据、requiredParts、collider 八角包络、socket 数值及同默认 options 重建确定性；不证明米制 UV 密度、结构合理性或 socket 功能接触。 |
| verify variants | 默认配置及各选项一个非默认代表值（若存在）；不穷举 values 或选项组合，不把抽样当全部通过。 |
| verify runtime | 采样 update/reset、检查可选 dispose 重复调用及共享材质释放事件、有限重复挂载与 console/pageerror/网络/控件；只提供有限运行证据，不证明全部生命周期边界、所有共享资源或 memory 回收。 |
| verify visual | 生成整体/正面/背面材质图及 clay/wire 图，visual 始终 `UNVERIFIED`；需要侧面、近景或动态姿态时另补，截图成功不是视觉通过。 |

以实际 report 的执行项、警告和失败为准；不提供完整 memory proof。下列完整质量要求未被自动报告覆盖时，单独执行或标为未执行，不补写自动 PASS。

- 用宿主真实调用方式测试 `root.userData.update(dt)`、`root.userData.reset()` 和可选 `root.userData.dispose()`；以普通步长、边界状态和宿主允许的大 dt 验证无 NaN、漂移、穿插、重复计时器或帧率依赖。数值容差按契约/运行环境确定，不硬编码全项目阈值。
- 检查动态节点未被 merge，转轴/滑轨正确，门不绕几何中心假转；验证打开后柜体确有内腔，挂点/碰撞按契约联动。reset 后与初始状态逐项核对。静态资产不伪造 hooks。
- 覆盖全部已声明离散变体及数值参数边界；组合太多时先定义有理由的覆盖矩阵，列出未覆盖项，不把抽样写成全部通过。每个变体复查 bbox、requiredParts、UV、碰撞及渲染。
- 重复 build→挂载→`userData.update`→`userData.reset`→卸载→`userData.dispose`，记录循环次数、基线、每轮 renderer.info 和回收后的 geometry/texture/material 趋势。当前 verify 自动报告不提供完整 memory proof；共享缓存预热后的稳定占用与泄漏分开报告，不依赖单次 heap 数值。
- 确认没有每 mesh 无条件 clone、着色钩子丢失、每帧分配、重复监听、残留 RAF 或共享 ctx.mats 被 dispose。明确 `ctx.sharedMaterials` 是宿主维护的 Set，作者不写入、删除、清空或伪造，不能把“未观察到释放事件”写成所有资源均已安全回收。切换资产后再加载可信参考，验证没有污染共享资源。
- 捕获 browser console、pageerror、资源失败与 WebGL 警告，记录详情及关联来源；不隐藏错误或清空日志后宣称通过。明确与该资产无关的问题依据及影响。
- 逐 LOD 实测三角形、draw calls、纹理/显存与构建/帧开销，在相同测量条件下对照预算；未有 LOD 实现时不得仅凭契约声明通过。

## 7. 证据包与状态写回

交付以下实际文件并给出相对路径；按目标项目约定保存到明确 root 内：

1. 原创 source、registry 条目及完整 design contract；列出修改文件，不包含版权不明原版源码复制品。
2. JSON/文本测试报告：命令、root、id、版本、hash/摘要、参考测量、几何、UV、collider corners、seed、dynamic、variants、memory、console 和预算结果。
3. 三角度最终材质 PNG、clay PNG、wire PNG 及必要近景/动态/变体图。
4. pass/fail/未执行清单、失败原因、未覆盖项和下一步；将命令未执行、浏览器不可用、r180 未恢复等明确列为未执行，不模糊写“基本通过”。

registry 根 schema 固定为 `{schemaVersion: 1, assets: []}`，初始 acceptance 保持 `catalog/geometry/visual/runtime: 'unverified'`。报告可记录 `PASS`/`FAIL`/`UNVERIFIED` 或未执行原因，但不把报告状态自动写回 registry；真正证据通过独立 report hash 绑定。当前 builder 拒绝非 unverified 状态，后续专门签证流程尚未实现，不能在当前版本手写 PASS。

把 catalog 视为需要证据聚合的目标，而不是命令结果：geometry/run 只有报告列明的有限自动检查，visual 始终 `UNVERIFIED`。将人工图片检查结论存为独立、hash 绑定的补充证据，不覆盖自动报告、不回写 registry；修改 source、options、seed 规则、材质或契约后旧报告不再证明当前版本，需复测。把 r180 full-scene 结果放在独立报告，不扩展现有 catalog 状态含义。
